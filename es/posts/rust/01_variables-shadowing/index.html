Rust - Básico - 01 - Sombreado de variables

2022-01-03 Rust

Sombreado de variables

Comprensión

En Rust, si una variable (let o let mut) llamada a se vuelve a declarar más adelante, ese comportamiento se llama shadowing (sombreado).

  • Las variables const no se pueden sombrear
  • El sombreado puede tener alcance de bloque ({})
  • El sombreado permite declarar un tipo nuevo reutilizando el mismo nombre de variable

Fuente

https://doc.rust-lang.org/book/ch03-01-variables-and-mutability.html#shadowing

fn main() {
    let x = 5;

    let x = x + 1;

    {
        let x = x * 2;
        println!("The value of x in the inner scope is: {}", x);
    }

    println!("The value of x is: {}", x);
}

Este programa vincula primero x al valor 5. Después sombrea x repitiendo let x =, toma el valor original y le suma 1, así que el valor de x pasa a ser 6. Luego, dentro de un alcance interno, la tercera sentencia let también sombrea x, multiplica el valor anterior por 2 y da a x el valor 12. Cuando ese alcance termina, el sombreado interno acaba y x vuelve a ser 6. Al ejecutar este programa, la salida es la siguiente:


$ cargo run
   Compiling variables v0.1.0 (file:///projects/variables)
    Finished dev [unoptimized + debuginfo] target(s) in 0.31s
     Running `target/debug/variables`
The value of x in the inner scope is: 12
The value of x is: 6

El sombreado es distinto de marcar una variable como mut, porque obtendremos un error en tiempo de compilación si intentamos reasignar accidentalmente esa variable sin usar la palabra clave let. Al usar let podemos hacer algunas transformaciones sobre un valor y dejar la variable inmutable una vez completadas esas transformaciones.

La otra diferencia entre mut y el sombreado es que, como en realidad estamos creando una variable nueva al volver a usar la palabra clave let, podemos cambiar el tipo del valor y reutilizar el mismo nombre. Por ejemplo, supongamos que el programa pide al usuario que indique cuántos espacios quiere entre un texto y otro introduciendo caracteres de espacio, pero en realidad queremos guardar esa entrada como un número:


    let spaces = "   ";
    let spaces = spaces.len();

Esta construcción está permitida porque la primera variable spaces es de tipo cadena, y la segunda variable spaces, que es una variable completamente nueva que casualmente tiene el mismo nombre que la primera, es de tipo numérico. El sombreado nos ahorra así tener que inventar nombres distintos, como spaces_str y spaces_num; en su lugar podemos reutilizar el nombre más simple, spaces. Sin embargo, si intentamos usar mut para esto, como se muestra aquí, obtendremos un error en tiempo de compilación:


    let mut spaces = "   ";
    spaces = spaces.len();

El error dice que no se nos permite mutar el tipo de una variable:


$ cargo run
   Compiling variables v0.1.0 (file:///projects/variables)
error[E0308]: mismatched types
 --> src/main.rs:3:14
  |
3 |     spaces = spaces.len();
  |              ^^^^^^^^^^^^ expected `&str`, found `usize`

For more information about this error, try `rustc --explain E0308`.
error: could not compile `variables` due to previous error
