2022-01-03 Rust

Estructuras

Comprensión

  • Sintaxis básica

    // declaración de tipo
struct User {
    active: bool,
    username: String,
    email: String,
    sign_in_count: u64,
}

// instanciación
let user1 = User {
    email: String::from("someone@example.com"),
    username: String::from("someusername123"),
    active: true,
    sign_in_count: 1,
};

// acceso y modificación
let mut user1 = User {
    email: String::from("someone@example.com"),
    username: String::from("someusername123"),
    active: true,
    sign_in_count: 1,
};
user1.email = String::from("anotheremail@example.com");

// field init shorthand
fn build_user(email: String, username: String) -> User {
    User {
        email,
        username,
        active: true,
        sign_in_count: 1,
    }
}

// struct update
let user2 = User {
    email: String::from("another@example.com"),
    ..user1
}
// aquí user1 se mueve, porque user1.username (de tipo String) se mueve a user2.username
// si al inicializar user2 se asigna username por separado, user1 no se mueve

  • Method

    Una function dentro de un impl de struct se llama method o associated function; un method y un field pueden tener el mismo nombre

    Pueden existir varios impl a la vez

    #[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

impl Rectangle {
    fn area(&self) -> u32 {  // method
        self.width * self.height
    }
		fn width(&self) -> bool {  // un method puede tener el mismo nombre que un field
        self.width > 0
    }
    fn square(size: u32) -> Rectangle {  // también se puede sin &self
        Rectangle {
            width: size,
            height: size,
        }
    }
}

// pueden coexistir varios impl
impl Rectangle {
    fn can_hold(&self, other: &Rectangle) -> bool {
        self.width > other.width && self.height > other.height
    }
}

fn main() {
    let rect1 = Rectangle {
        width: 30,
        height: 50,
    };

    println!(
        "The area of the rectangle is {} square pixels.",
        rect1.area()
    );

		if rect1.width() {
        println!("The rectangle has a nonzero width; it is {}", rect1.width);
    }
}

Crear instancias a partir de otras instancias con la sintaxis de actualización de struct

A menudo resulta útil crear una instancia nueva de un struct que use la mayoría de los valores de una instancia antigua pero cambie algunos. Puedes hacerlo con la sintaxis de actualización de struct.

Primero, el listado 5-6 muestra cómo creamos una instancia nueva de User en user2 sin la sintaxis de actualización. Ponemos un valor nuevo para email pero por lo demás usamos los mismos valores de user1 que creamos en el listado 5-2.


    let user2 = User {
        active: user1.active,
        username: user1.username,
        email: String::from("another@example.com"),
        sign_in_count: user1.sign_in_count,
    };

Listado 5-6: crear una instancia nueva de User usando uno de los valores de user1

Con la sintaxis de actualización de struct podemos lograr el mismo efecto con menos código, como muestra el listado 5-7. La sintaxis .. indica que los campos restantes que no se establecen explícitamente deben tener el mismo valor que los campos de la instancia dada.


    let user2 = User {
        email: String::from("another@example.com"),
        ..user1
    };

Listado 5-7: usar la sintaxis de actualización de struct para poner un valor nuevo de email en una instancia de User pero usar el resto de los valores de user1

El código del listado 5-7 también crea una instancia en user2 que tiene un valor distinto para email pero los mismos valores en los campos username, active y sign_in_count de user1. El ..user1 debe ir al final para indicar que cualquier campo restante debe tomar sus valores de los campos correspondientes de user1, pero podemos elegir especificar valores para tantos campos como queramos y en cualquier orden, sin importar el orden de los campos en la definición del struct.

Fíjate en que la sintaxis de actualización de struct es como una asignación con = porque mueve los datos, tal como vimos en la sección «Formas en que las variables y los datos interactúan: move» . En este ejemplo ya no podemos usar user1 después de crear user2, porque el String del campo username de user1 se movió a user2. Si hubiéramos dado a user2 valores nuevos de String tanto para email como para username, y por tanto solo hubiéramos usado los valores de active y sign_in_count de user1, entonces user1 seguiría siendo válido después de crear user2. Los tipos de active y sign_in_count son tipos que implementan el trait Copy, así que se aplicaría el comportamiento que comentamos en la sección «Datos solo en la pila: Copy» .
