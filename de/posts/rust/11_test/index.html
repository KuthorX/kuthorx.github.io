Rust - Grundlagen - 11 - Tests

2022-01-03 Rust

Tests

Insgesamt sind die Testfunktionen von Rust einfach, aber umfassend genug für testgetriebene Entwicklung. Leider sind in meinem Arbeitsumfeld die Ressourcen für Iterationen meist knapp und die Anforderungen zahlreich, sodass sich dieser Ansatz nicht gut eignet. Werden Tests erst später ergänzt, sind Unit- und Integrationstests sehr aufwendig.

Verständnis

  • Grundlegende Syntax

    
pub fn greeting(name: &str) -> String {
    String::from("Hello!")
}

pub struct Guess {
    value: i32,
}

impl Guess {
    pub fn new(value: i32) -> Guess {
        if value < 1 || value > 100 {
            panic!("Guess value must be between 1 and 100, got {}.", value);
        }

        Guess { value }
    }
}

#[cfg(test)]
mod tests {
		use super::*;
    #[test]
    fn it_works() {
				// Auch assert_ne! ist verfügbar
        assert_eq!(2 + 2, 4);
    }

		#[test]
    fn will_fail() {
        panic!("Make this test fail");
    }

		#[test]
    fn greeting_contains_name() {
        let result = greeting("Carol");
				// Wenn assert nicht der Erwartung entspricht, kann ein Hinweis ausgegeben werden
        assert!(
            result.contains("Carol"),
            "Greeting did not contain name, value was `{}`",
            result
        );
    }

		#[test]
		#[should_panic]
		// should_panic prüft, ob panic auftritt
		fn greater_than_100() {
        Guess::new(200);
    }
}

#[cfg(test)]
mod tests2 {
    #[test]
		// Mit Result<T, E> als Rückgabewert lässt sich der should_panic-Trait nicht verwenden
    fn it_works() -> Result<(), String> {
        if 2 + 2 == 4 {
            Ok(())
        } else {
            Err(String::from("two plus two does not equal four"))
        }
    }
}
