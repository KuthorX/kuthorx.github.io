  • Generics, Variante 2: Traits und Trait Bounds

    Ein Trait beschreibt eine Eigenschaft. Grundsätzlich kann er Structs, Funktionsparameter und Rückgabewerte mit einer Eigenschaft versehen.

    Bei einem Struct kann der Trait festlegen, dass es die darin deklarierten Methoden besitzt, ähnlich wie ein Java-interface.

    impl structA for traitA

    Bei einem generischen Typ kann der Trait festlegen, dass nur konkrete Typen mit diesen Eigenschaften (Trait Bounds) die entsprechende Methodensammlung erhalten.

    impl<T: traitA + traitB + ...> structA<T> {...}

    Bei Funktionsparametern kann der Trait einschränken, dass nur Parameter mit den entsprechenden Eigenschaften verwendet werden dürfen (Polymorphie).

    pub fn notify(item: &impl Summary) {...}

    Bei einem Rückgabewert kann der Trait garantieren, dass der Rückgabewert diese Eigenschaft besitzt.

Leistung von Code mit Generics

Vielleicht fragst du dich, ob die Verwendung generischer Typparameter Laufzeitkosten verursacht. Die gute Nachricht: Rust implementiert Generics so, dass Code mit generischen Typen nicht langsamer läuft als Code mit konkreten Typen.

Rust erreicht dies durch Monomorphisierung des generischen Codes zur Kompilierzeit. Monomorphisierung bedeutet, generischen Code in spezifischen Code umzuwandeln, indem beim Kompilieren die verwendeten konkreten Typen eingesetzt werden.

…

Der Compiler verwendet drei Regeln, um Lebenszeiten von Referenzen ohne explizite Annotationen zu bestimmen. Die erste Regel betrifft Eingabe-Lebenszeiten, die zweite und dritte Ausgabe-Lebenszeiten. Wenn nach allen drei Regeln noch Referenzen mit unbestimmter Lebenszeit übrig bleiben, bricht der Compiler mit einem Fehler ab. Die Regeln gelten sowohl für fn-Definitionen als auch für impl-Blöcke.

Die erste Regel: Jeder Referenzparameter erhält einen eigenen Lebenszeitparameter. Eine Funktion mit einem Parameter erhält also einen Parameter: fn foo<'a>(x: &'a i32); eine Funktion mit zwei Parametern erhält zwei getrennte Parameter: fn foo<'a, 'b>(x: &'a i32, y: &'b i32); und so weiter.

Die zweite Regel: Gibt es genau einen Eingabe-Lebenszeitparameter, wird diese Lebenszeit allen Ausgabe-Lebenszeitparametern zugewiesen: fn foo<'a>(x: &'a i32) -> &'a i32.

Die dritte Regel: Gibt es mehrere Eingabe-Lebenszeitparameter und ist einer davon &self oder &mut self, weil es sich um eine Methode handelt, wird die Lebenszeit von self allen Ausgabe-Lebenszeitparametern zugewiesen. Dadurch sind Methoden angenehmer zu lesen und zu schreiben, weil weniger Symbole nötig sind.
