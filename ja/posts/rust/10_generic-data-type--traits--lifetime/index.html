ジェネリック: データ型・trait・ライフタイム

理解する

  • ジェネリックの表現 1: データ型

    // ジェネリックの宣言 - struct
struct Point<T> {
    x: T,
    y: T,
}
let point = Point { x: 5, y: 4 }; // 同一の型でなければなりません
struct PointDiffType<T, U> {
    x: T,
    y: U,
}
let point_diff_type = PointDiffType{ x: 5, y: 4.0 }; // 異なる型

// ジェネリックの宣言 - impl
impl<T> Point<T> {
    fn x(&self) -> &T {
        &self.x
    }
}

// ジェネリックの宣言 - enum
enum Option<T> {
    Some(T),
    None,
}
enum Result<T, E> {
    Ok(T),
    Err(E),
}

// mix-up の 1 つの実装
struct Point<T, U> {
    x: T,
    y: U,
}
impl<T, U> Point<T, U> {
		// ジェネリックの高い柔軟性により、ここでは field を巧みに交差させて 3 つ目の新しいジェネリックのインスタンスを組み立てています
    // この構文は middleware に使えます
    fn mixup<V, W>(self, other: Point<V, W>) -> Point<T, W> {
        Point {
            x: self.x,
            y: other.y,
        }
    }
}
fn main() {
    let p1 = Point { x: 5, y: 10.4 };
    let p2 = Point { x: "Hello", y: 'c' };
    let p3 = p1.mixup(p2);
    println!("p3.x = {}, p3.y = {}", p3.x, p3.y);
}

  • ジェネリックを使っても実行時の性能には影響しない

    コンパイル段階で Monomorphization process がジェネリックを具体的な型へ変換するためです。

    // たとえば Some を使ったジェネリックのコード
let integer = Some(5);
let float = Some(5.0);
// コンパイル時に次のコードへ Monomorphization されます
enum Option_i32 {
    Some(i32),
    None,
}
enum Option_f64 {
    Some(f64),
    None,
}
fn main() {
    let integer = Option_i32::Some(5);
    let float = Option_f64::Some(5.0);
}

  • ジェネリックの表現 2: Traits と Trait Bounds

    Trait は「特性」を意味します。基本的な使い方では、struct、関数引数、関数の戻り値に特性を付けられます。

    struct では、その特性で宣言した method を持つことを明示できます。Java の interface に似ています。

    impl structA for traitA

    generic type では、対応する concrete type がこれらの特性(trait bound とも呼ばれます)を持つ場合だけ、対応する関数群を持てると示せます。

    impl<T: traitA + traitB + ...> structA<T> {...}

    関数引数では、対応する特性を持つ引数だけを受け取れるよう制限できます(多態性)。

    pub fn notify(item: &impl Summary) {...}

    関数の戻り値では、戻り値が必ずその特性を持つことを明示できます。

    // Defining a Trait
pub trait Summary {
    fn summarize(&self) -> String;
}

// Implementing a Trait on a Type
pub struct NewsArticle {
    pub headline: String,
    pub location: String,
    pub author: String,
    pub content: String,
}

impl Summary for NewsArticle {
    fn summarize(&self) -> String {
        format!("{}, by {} ({})", self.headline, self.author, self.location)
    }
}

// Default Implementations
pub trait Summary {
    fn summarize(&self) -> String {
        String::from("(Read more...)")
    }
}

// Default Implementations から他の impl を呼べます
pub trait Summary {
    fn summarize_author(&self) -> String;

    fn summarize(&self) -> String {
        format!("(Read more from {}...)", self.summarize_author())
    }
}

// Traits as Parameters
pub fn notify(item: &impl Summary) {
    println!("Breaking news! {}", item.summarize());
}

// generic type で trait bounds を指定できます
pub fn notify<T: Summary>(item1: &T, item2: &T) {}

// 複数の trait の場合 1 - + 演算子を使う
pub fn notify(item: &(impl Summary + Display)) {
pub fn notify<T: Summary + Display>(item: &T) {

// 複数の trait の場合 2 - where を使う
fn some_function<T, U>(t: &T, u: &U) -> i32
    where T: Display + Clone,
          U: Clone + Debug

// Returning Types that Implement Traits
fn returns_summarizable() -> impl Summary {
    Tweet {
        username: String::from("horse_ebooks"),
        content: String::from(
            "of course, as you probably already know, people",
        ),
        reply: false,
        retweet: false,
    }
}

// trait bounds によって、対応する trait を持つ generic type だけが対応する method を持てるようにできます
use std::fmt::Display;

struct Pair<T> {
    x: T,
    y: T,
}

impl<T> Pair<T> {
    fn new(x: T, y: T) -> Self {
        Self { x, y }
    }
}

impl<T: Display + PartialOrd> Pair<T> {
    fn cmp_display(&self) {
        if self.x >= self.y {
            println!("The largest member is x = {}", self.x);
        } else {
            println!("The largest member is y = {}", self.y);
        }
    }
}

  • ジェネリックの表現 3: ライフタイム

    &i32        // a reference
&'a i32     // a reference with an explicit lifetime
&'a mut i32 // a mutable reference with an explicit lifetime
// 主に function の定義時に使います
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}
// struct に使えます
struct ImportantExcerpt<'a> {
    part: &'a str,
}

// Lifetime Elision - 3 つの規則を活用
fn first_word(s: &str) -> &str {...}

// static ライフタイム。プログラムの実行中ずっと利用できます
let s: &'static str = "I have a static lifetime.";

    コンパイラーは、明示的な注釈がない場合、3 つのルールで reference の lifetime を計算します。

    1 のルールは、reference である各パラメーターが固有の lifetime parameter を持つことです。

    1 条: reference の各入力パラメーターには独自の lifetime parameter があります。

    2 のルールは、入力 lifetime parameter が 1 つだけなら、その lifetime をすべての出力 lifetime parameter に割り当てることです。

    2 条: 入力 lifetime parameter が 1 つだけなら、それをすべての出力 lifetime parameter に割り当てます。

    3 のルールは、入力 lifetime parameter が複数あり、そのうち 1 つが method の &self または &mut self なら、self の lifetime をすべての出力 lifetime parameter に割り当てることです。

    3 条: 入力 lifetime parameter が複数あり、その 1 つが &self または &mut self(method)なら、self の lifetime parameter をすべての出力 lifetime parameter に割り当てます。

  • 3 つの表現を組み合わせて使う

    use std::fmt::Display;

fn longest_with_an_announcement<'a, T>(
    x: &'a str,
    y: &'a str,
    ann: T,
) -> &'a str
where
    T: Display,
{
    println!("Announcement! {}", ann);
    if x.len() > y.len() {
        x
    } else {
        y
    }
}

ジェネリックを使うコードのパフォーマンス

generic type parameter を使うと実行時コストが発生するのでは、と疑問に思うかもしれません。Rust のジェネリック実装では、generic type を使っても concrete type の場合よりコードが遅くなることはありません。

Rust は、ジェネリックを使うコードをコンパイル時に monomorphization することでこれを実現します。Monomorphization とは、コンパイル時に使われる concrete type を埋め、generic code を具体的なコードへ変換する処理です。

…

コンパイラーは、明示的な注釈がない場合、3 つのルールで reference の lifetime を判断します。 1 のルールは入力 lifetime、 2 と 3 のルールは出力 lifetime に適用されます。3 つのルールを適用しても lifetime を判断できない reference が残ると、コンパイラーはエラーで停止します。これらのルールは fn 定義と impl ブロックの両方に適用されます。

1 のルールは、reference である各パラメーターが固有の lifetime parameter を持つことです。 In other words, a function with one parameter gets one lifetime parameter: fn foo<'a>(x: &'a i32); a function with two parameters gets two separate lifetime parameters: fn foo<'a, 'b>(x: &'a i32, y: &'b i32); and so on.

2 のルールは、入力 lifetime parameter が 1 つだけなら、その lifetime をすべての出力 lifetime parameter に割り当てることです。: fn foo<'a>(x: &'a i32) -> &'a i32.

3 のルールは、入力 lifetime parameter が複数あり、そのうち 1 つが method の &self または &mut self なら、self の lifetime をすべての出力 lifetime parameter に割り当てることです。This third rule makes methods much nicer to read and write because fewer symbols are necessary.
