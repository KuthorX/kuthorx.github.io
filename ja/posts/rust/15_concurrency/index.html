Rust - Basic - 15 - Concurrency

2022-01-03 Rust

並行性とは

理解する

並行・並列処理は、メッセージパッシング(Message-passing)または状態共有(Shared-state)で実現できます。

スレッド

並行処理では次の点に注意が必要です。

  • データ競合

    スレッドがデータやリソースへ一貫しない順序でアクセスする競合状態。

  • デッドロック

    2 つのスレッドが互いに相手の保持するリソースの使用終了を待ち続け、どちらも進めなくなる状態。

  • 再現しにくいバグ

    特定の状況でだけ発生し、安定して再現・修正するのが難しいバグ。

Green Thread はプログラミング言語レベルの thread であり、OS が提供する thread 機能とは完全には同じではありません。

use std::thread;
use std::time::Duration;

fn main() {
    let handle = thread::spawn(|| {  // ここでのクロージャに入力引数が必要なら、move を明示的に宣言する必要があります
        for i in 1..10 {
            println!("hi number {} from the spawned thread!", i);
            thread::sleep(Duration::from_millis(1));  // この時点で OS が他のスレッドへ実行を切り替える機会が得られます
        }
    });

    handle.join().unwrap();  // join で全スレッドの実行終了を待ちます(そうしないと後続のコードは実行されません)

    for i in 1..5 {
        println!("hi number {} from the main thread!", i);
        thread::sleep(Duration::from_millis(1));
    }
}

メッセージパッシング

  • Channel の基本的な書き方

    use std::sync::mpsc;  // multiple producer single consumer

fn main() {
    let (tx, rx) = mpsc::channel();  // transmitter, receiver

		thread::spawn(move || {
        let val = String::from("hi");
        tx.send(val).unwrap();  // ここで val は ownership が move されます
    });

		let received = rx.recv().unwrap();  // try_recv を使えばブロックされません
    println!("Got: {}", received);
}

  • 複数 producer/transmitter と複数メッセージの受信

    use std::sync::mpsc;
use std::thread;
use std::time::Duration;

fn main() {
    let (tx, rx) = mpsc::channel();

		// 後続のクロージャ内で tx の ownership が move されるため
    // ここで事前に tx1 を clone して multi producer を実現する必要があります
		let tx1 = tx.clone();
		thread::spawn(move || {
        let vals = vec![
            String::from("hi"),
            String::from("from"),
            String::from("the"),
            String::from("thread"),
        ];

        for val in vals {
            tx1.send(val).unwrap();
            thread::sleep(Duration::from_secs(1));
        }
    });

    thread::spawn(move || {
        let vals = vec![
            String::from("more"),
            String::from("messages"),
            String::from("for"),
            String::from("you"),
        ];

        for val in vals {
            tx.send(val).unwrap();
            thread::sleep(Duration::from_secs(1));
        }
    });

		// 前の例と比べて for-in loop を使っている点に注意
    for received in rx {  
        println!("Got: {}", received);
    }
}

状態共有とは

Mutex(Mutual Exclusion、相互排他)の一例は、同時に 1 スレッドだけが特定データへアクセスできることです。

スレッドは mutex のデータへアクセスする前に lock を取得する必要があります。lock は mutex の一部であり、誰がデータへ排他的にアクセスできるかを追跡します。そのため mutex は、ロック機構で保持データを保護すると説明されます。

Mutex は次の 2 つのルールがあるため扱いが難しいものです。

  • データを使う前にロック取得を試みる必要があります。

    You must attempt to acquire the lock before using the data.

  • mutex が保護するデータの使用後は、他のスレッドがロックを取得できるよう解放しなければなりません。

    When you’re done with the data that the mutex guards, you must unlock the data so other threads can acquire the lock.

mutex の管理は難しいため、channel を好む人も多くいます。しかし Rust の型システムと所有権ルールにより、ロックを誤って取得・解放することはありません。

  • Mutex の基本的な書き方

    use std::sync::Mutex;

fn main() {
    let m = Mutex::new(5);

    {
        let mut num = m.lock().unwrap();  // lock を呼んでロックを取得
        *num = 6;
    }

    println!("m = {:?}", m);
}

  • 複数スレッドで Mutex を共有する

    use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));
    let mut handles = vec![];

    for _ in 0..10 {
        let counter = Arc::clone(&counter);
        let handle = thread::spawn(move || {
            let mut num = counter.lock().unwrap();
            *num += 1;
        });
        handles.push(handle);
    }

    for handle in handles {
        handle.join().unwrap();
    }

    println!("Result: {}", *counter.lock().unwrap());
}

Send と Sync trait

Send trait を実装する型は、ownership をスレッド間で移せます。

Sync trait を実装する型は、複数スレッドからアクセスできます。

Sync は Send の性質を含むことが分かります。

Arc<T> によるアトミック参照カウント

Fortunately, Arc<T> is a type like Rc<T> that is safe to use in concurrent situations. The a stands for atomic, meaning it’s an atomically reference counted type. Atomics are an additional kind of concurrency primitive that we won’t cover in detail here: see the standard library documentation for [std::sync::atomic](https://doc.rust-lang.org/std/sync/atomic/index.html) for more details. At this point, you just need to know that atomics work like primitive types but are safe to share across threads.

では、なぜすべてのプリミティブ型が atomic ではないのか疑問に思うかもしれません。 and why standard library types aren’t implemented to use Arc<T> by default. The reason is that thread safety comes with a performance penalty that you only want to pay when you really need to. If you’re just performing operations on values within a single thread, your code can run faster if it doesn’t have to enforce the guarantees atomics provide.
