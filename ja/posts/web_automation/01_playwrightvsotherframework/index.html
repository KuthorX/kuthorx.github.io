Playwright 入門ガイド

2022-01-31 ウェブ自動化

基礎メモ

主に https://blog.logrocket.com/playwright-vs-puppeteer/ を参考にしたメモです。

Chrome が headless browser をサポートして以来 、個人開発者が支えてきた複雑で細かな技術（PhantomJS、Selenium など）は影を潜め、Web 自動化フレームワークは 激しく 更新を繰り返すようになりました。

Puppeteer について：Chrome 公式が支援する（DevTools Protocol ベースの）フレームワークで、PhantomJS（WebDriver プロトコルベース）より安定しています。

Playwright について：開発チームは Puppeteer から移ってきました。Puppeteer と比べて：

  1. API が似ている（つまり導入コストがほとんどない）
  2. 一部の API はより Ergonomic（つまりセマンティクスが優れている）。書き方の面では、さまざまな種類のデバイスを手軽に模擬できる
  3. Firefox、WebKit にも対応するが、対応度は低い（将来 Puppeteer のチームと「共同開発」できるかもしれない……）

技術選定 について：Playwright / Puppeteer を選ぶにせよ、Cypress / PhantomJS / Selenium（workaround は多いが同時に flaky でもある）を選ぶにせよ、次の点を考える必要があります：

  1. クロスブラウザ対応（この記事によれば、現時点で最も優れているのは Playwright だが、Puppeteer や Cypress がいつまでも遅れていると誰が保証できるだろう？）
  2. 長期サポート（これは言うまでもない気がする……）
  3. 具体的な業務に合わせた分析（言うまでもない……）
